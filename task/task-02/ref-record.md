# md2pdf

一个高效、灵活的 Python 命令行工具，用于将 Markdown 文件转换为高质量、排版精美的 PDF 文档。

## 项目背景

在日常技术写作与文档管理中，Markdown 因其轻量和易读性备受青睐。然而，在正式分享、打印或归档时，通常需要排版稳定的 PDF 格式。传统的转换工具往往存在配置繁琐、样式难以定制、批量处理效率低下等痛点。`md2pdf` 旨在弥合这一鸿沟，提供开箱即用、高度可定制的 Markdown 到 PDF 转换方案。

## 核心特性

- 🚀 **极简操作**：纯命令行驱动，零配置即可生成标准 PDF。
- 🎨 **自定义主题**：支持通过 CSS 文件注入样式，完美契合企业品牌规范或个人审美。
- 📑 **智能目录**：自动解析 Markdown 标题层级，生成带有页码和书签的 PDF 目录（TOC, Table of Contents）。
- 📦 **批量处理**：支持单文件、多文件通配符及整个目录的递归批量转换。

## 安装

确保你的环境已安装 Python 3.8 及以上版本。推荐使用 `pip` 进行安装：

```bash
pip install md2pdf
```

> **提示**：`md2pdf` 底层依赖系统级的渲染引擎。如果在 Linux/macOS 上遇到渲染问题，请参考 [注意事项](#注意事项) 安装相关系统依赖。

## 快速开始

将单个 Markdown 文件转换为 PDF：

```bash
md2pdf README.md -o README.pdf
```

## 使用指南

### 1. 基本用法

查看所有可用的命令行参数和帮助信息：

```bash
md2pdf --help
```

### 2. 自定义主题

你可以通过传入自定义的 CSS 文件来控制 PDF 的字体、颜色、页边距等排版细节。

```bash
md2pdf document.md -o document.pdf --theme my_theme.css
```

**主题文件示例 (`my_theme.css`)**：
```css
/* 设置正文字体与行高 */
body {
    font-family: "Noto Sans SC", sans-serif;
    line-height: 1.6;
    color: #333;
}

/* 自定义代码块样式 */
pre {
    background-color: #f4f4f4;
    padding: 10px;
    border-radius: 4px;
}
```

### 3. 生成目录 (TOC)

使用 `--toc` 参数，工具会自动提取 Markdown 中的 `#` 到 `######` 标题，在 PDF 首页生成可点击跳转的目录，并添加 PDF 书签。

```bash
md2pdf manual.md -o manual.pdf --toc
```

### 4. 批量转换

支持使用通配符处理多个文件，或使用 `--batch` 处理整个目录。

**批量转换当前目录下的所有 `.md` 文件：**
```bash
md2pdf *.md --outdir ./pdf_output
```

**递归转换指定目录及其子目录下的所有文件：**
```bash
md2pdf ./docs --batch --outdir ./pdf_output
```

## 注意事项

### 1. 中文字体渲染
PDF 生成时若出现中文乱码或显示为“豆腐块”，通常是因为系统缺少中文字体。
- **解决方案**：请在操作系统中安装中文字体（如 `Noto Sans SC`、`思源黑体` 等），并在自定义 CSS 的 `font-family` 中显式指定该字体。

### 2. 系统级依赖
本工具依赖底层 HTML 到 PDF 的渲染引擎。
- **macOS**：通常无需额外配置。
- **Linux (Ubuntu/Debian)**：需安装 Pango 和 Cairo 等依赖库。
  ```bash
  sudo apt-get install libpango-1.0-0 libpangoft2-1.0-0 libcairo2
  ```
- **Windows**：确保安装了最新的 Visual C++ Redistributable。

### 3. 图片路径处理
- 推荐使用**相对路径**引用图片（如 `![img](./images/pic.png)`）。
- 工具会自动将相对路径解析为基于 Markdown 文件所在目录的绝对路径。若使用网络 URL，请确保运行环境具备外网访问权限。

### 4. 分页控制
若需要在 Markdown 中强制分页，可在需要分页的位置插入以下 HTML 标签：
```html
<div style="page-break-after: always;"></div>
```

# 用户管理 REST API 接口文档

## 1. 概述

本文档定义了用户管理模块的 RESTful API 接口规范。该模块提供用户注册、登录、信息获取及更新等核心功能。

**基础信息**
* **Base URL**: `https://api.example.com/v1`
* **数据格式**: 请求与响应均使用 `application/json`
* **字符编码**: `UTF-8`

---

## 2. 认证机制 (JWT)

除注册和登录接口外，其余接口均需进行身份认证。本系统采用 **JWT (JSON Web Token)** 进行状态无状态的认证。

* **JWT 简介**：JWT 是一种紧凑且自包含的令牌，服务器通过验证令牌的数字签名来确认用户身份，无需在服务器端存储 Session。
* **传递方式**：在 HTTP 请求头 (Header) 中添加 `Authorization` 字段。
* **格式**：`Authorization: Bearer <your_token>`

> **注**：`Bearer` 是 HTTP 认证方案的一种，表示其后跟随的是访问令牌。

---

## 3. 接口详情

### 3.1 用户注册

创建新用户账户。

* **接口路径**: `/users/register`
* **请求方法**: `POST`
* **认证要求**: 无

**请求参数 (Body)**

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :---: | :--- |
| username | string | 是 | 用户名，4-20个字符，支持字母和数字 |
| password | string | 是 | 密码，至少8位，需包含字母和数字 |
| email | string | 是 | 电子邮箱地址 |

**请求示例**

```bash
curl -X POST https://api.example.com/v1/users/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "johndoe",
    "password": "SecurePass123",
    "email": "john@example.com"
  }'
```

**响应示例 (成功)**

```json
{
  "code": 200,
  "message": "Registration successful",
  "data": {
    "user_id": "usr_8f7d9a2b",
    "username": "johndoe",
    "created_at": "2023-10-27T10:00:00Z"
  }
}
```

---

### 3.2 用户登录

验证用户凭证并签发 JWT 令牌。

* **接口路径**: `/users/login`
* **请求方法**: `POST`
* **认证要求**: 无

**请求参数 (Body)**

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :---: | :--- |
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |

**请求示例**

```bash
curl -X POST https://api.example.com/v1/users/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "johndoe",
    "password": "SecurePass123"
  }'
```

**响应示例 (成功)**

```json
{
  "code": 200,
  "message": "Login successful",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "Bearer",
    "expires_in": 7200
  }
}
```
> **注**：`expires_in` 单位为秒，示例中表示令牌有效期为 2 小时。

---

### 3.3 获取当前用户信息

获取已登录用户的详细资料。

* **接口路径**: `/users/me`
* **请求方法**: `GET`
* **认证要求**: 需要 JWT

**请求头 (Headers)**

| 参数名 | 必填 | 说明 |
| :--- | :---: | :--- |
| Authorization | 是 | 格式：`Bearer <access_token>` |

**请求示例**

```bash
curl -X GET https://api.example.com/v1/users/me \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

**响应示例 (成功)**

```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "user_id": "usr_8f7d9a2b",
    "username": "johndoe",
    "email": "john@example.com",
    "nickname": "John Doe",
    "avatar_url": "https://cdn.example.com/avatars/default.png",
    "created_at": "2023-10-27T10:00:00Z",
    "last_login_at": "2023-10-28T08:30:00Z"
  }
}
```

---

### 3.4 更新用户信息

修改当前登录用户的个人资料。仅传递需要修改的字段。

* **接口路径**: `/users/me`
* **请求方法**: `PUT`
* **认证要求**: 需要 JWT

**请求参数 (Body)**

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :---: | :--- |
| nickname | string | 否 | 昵称，最长 30 个字符 |
| avatar_url | string | 否 | 头像 URL |
| email | string | 否 | 新邮箱地址（需重新验证） |

**请求示例**

```bash
curl -X PUT https://api.example.com/v1/users/me \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -H "Content-Type: application/json" \
  -d '{
    "nickname": "Johnny",
    "avatar_url": "https://cdn.example.com/avatars/johnny.png"
  }'
```

**响应示例 (成功)**

```json
{
  "code": 200,
  "message": "Profile updated successfully",
  "data": {
    "user_id": "usr_8f7d9a2b",
    "username": "johndoe",
    "nickname": "Johnny",
    "avatar_url": "https://cdn.example.com/avatars/johnny.png",
    "updated_at": "2023-10-28T09:00:00Z"
  }
}
```

## 4. 全局错误响应格式

当请求发生错误时，API 将返回统一的 JSON 错误结构：

```json
{
  "code": 400,
  "message": "Invalid request parameters",
  "details": [
    {
      "field": "email",
      "issue": "Invalid email format"
    }
  ]
}
```

**常见 HTTP 状态码说明**

| 状态码 | 说明 | 场景示例 |
| :--- | :--- | :--- |
| **200** | 成功 | 请求处理成功 |
| **400** | 请求参数错误 | 缺少必填字段、格式校验失败 |
| **401** | 未授权 | 未提供 Token、Token 过期或无效 |
| **403** | 禁止访问 | 权限不足（本模块暂未涉及复杂权限） |
| **404** | 资源不存在 | 请求的路径或用户 ID 不存在 |
| **409** | 资源冲突 | 注册时用户名或邮箱已被占用 |
| **429** | 请求过于频繁 | 触发限流策略（如登录接口连续失败） |
| **500** | 服务器内部错误 | 服务端未捕获的异常 |

---

## 5. 注意事项

1. **传输安全**：所有 API 请求必须通过 **HTTPS** 进行，以防止 JWT 令牌和密码在传输过程中被窃听。
2. **密码安全**：客户端不应在本地明文存储密码；服务端必须使用安全的哈希算法（如 bcrypt 或 Argon2）存储密码，严禁明文存储。
3. **Token 管理**：
   * 客户端应妥善保存 `access_token`（如使用 HttpOnly Cookie 或安全的本地存储）。
   * 当收到 `401 Unauthorized` 响应时，客户端应引导用户重新登录。
4. **数据脱敏**：在返回用户信息时，服务端已过滤掉密码哈希等敏感字段，请勿尝试在请求中传递或要求返回此类数据。
5. **幂等性**：`GET` 和 `PUT` 接口具有幂等性，多次执行相同请求产生的副作用与执行一次相同。`POST` 接口（如注册）不具备幂等性，重复提交可能返回 `409 Conflict`。
